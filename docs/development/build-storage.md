# 开发构建存储与清理

本文面向开发者，不是安装后的用户文件位置说明。所有相对路径以当前仓库根目录为准。

| 路径 | 用途 |
| --- | --- |
| `.artifacts/installers/<版本>-<唯一标识>/` | 新安装包、校验和与构建证据 |
| `.artifacts/runtime/<唯一标识>/` | 新的 Lite/QEMU 构建输出 |
| `.artifacts/history/` | 维护脚本归档的旧构建及清单 |
| `.tmp-v2-native/` | 开发缓存、临时文件、测试和解包审核 |
| `electron/generated/` | 打包资源阶段 |

`dist:native` 每次生成独立目录；runtime 仍须明确选择且来源校验通过。
旧文档中的根目录 `dist-*` 路径可能已归档，不是当前默认输出，也不是公开下载地址。

## 存储位置

建议把仓库和构建输出放在空间充足的卷。项目脚本提供本地构建缓存和临时环境，但不会迁移 Docker 数据目录、系统全局设置或安装后用户资料。
Go 模块缓存并非所有入口都自动迁移；需要调整时应使用项目进程级配置，避免修改其他项目。
Windows Go race 测试应使用 ASCII 临时路径；远端 CI 的临时环境适配不等于修改用户系统。

## 归档与恢复

仓库根目录运行：

```powershell
./scripts/archive-native-builds.ps1
# 阅读预览后再执行
./scripts/archive-native-builds.ps1 -Apply
```

脚本只处理其规则允许的旧根目录构建，保留近期输入并跳过正在使用的目录；不处理源码、其他工作树、账号或音乐。
归档是移动而不是删除，不保证释放同卷磁盘空间。
恢复前查归档清单中的原路径与目标路径，确认范围正确、原路径不存在，再按清单恢复；不要用新 runtime 覆盖历史证据。
