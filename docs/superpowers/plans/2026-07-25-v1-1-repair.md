# Apple Music Downloader v1.1 Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven development or execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Docker Web, Go CLI, and Windows Electron share one safe, persistent, serial download service with a reproducible release path.

**Architecture:** The imported Go downloader remains the media implementation, but it is called through a per-job engine boundary. A SQLite-backed service owns job state, file records, SSE replay, cancellation, wrapper capability reporting, and the v1 compatibility adapters. The browser and Electron shell only consume the v1 API; Docker owns the wrapper lifecycle.

**Tech Stack:** Go 1.23, `modernc.org/sqlite`, net/http, SSE, Docker Compose, vanilla browser UI, Electron/electron-builder, GitHub Actions.

### Task 3: Add persistent job storage and serial worker

**Files:**
- Create: `apple-music-downloader/internal/jobs/store.go`, `migrations.go`, `service.go`, `worker.go`, `events.go`, `files.go`
- Modify: `apple-music-downloader/main.go`
- Test: `apple-music-downloader/internal/jobs/service_test.go`, `store_test.go`, `worker_test.go`

- [ ] Open `/app/data/jobs.db` using the pure-Go SQLite driver, enable WAL and migrations, and store only URL/job metadata, track state, bounded event text, and relative file paths—never passwords or tokens.
- [ ] Model `queued → running → cancelling → succeeded|partial|failed|cancelled`, plus durable `interrupted` recovery state. On startup continue queued jobs and mark in-flight jobs interrupted.
- [ ] Execute one job at a time. Cancellation must remove queued work or cancel the active engine context and persist `cancelled` within two seconds where the engine cooperates.
- [ ] Record at most 500 events per job with monotonically increasing IDs and provide replay after `Last-Event-ID`.
- [ ] Index existing files once as unmanaged without moving, renaming, deleting, or age-based cleanup. Ensure overwrite uses a same-directory temporary file followed by validation and atomic rename.
