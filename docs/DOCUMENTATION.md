# 文档维护约定

## 面向读者组织内容

- 根 README：项目用途、功能、下载、开发入口和必要限制。
- 用户指南：界面操作、已知限制和可执行的故障反馈步骤。
- 开发文档：当前源码结构、接口、安全约束、环境和命令。
- 发布记录：固定标签、源码提交、附件身份和当次实际验证范围。
- 第三方资料：版权、许可证、来源、对应源码与未完成事项。

不在公开指南中保留个人机器路径、临时工作树状态、聊天指令、日期化调试日志或阶段工作汇报。有长期价值的结论应整理到架构或测试指南；变更讨论使用 Issue、PR 和提交记录。

原始许可证、上游声明和锁定归档清单保留原文及校验身份，不因文字统一而改写。安装 GUID、模块路径和数据目录中的旧名称属于兼容约束，见[兼容说明](development/compatibility.md)。

## 事实来源

命令以 `package.json`、工作流和构建脚本为准；组件版本以锁文件为准；已发布文件以对应 Release 的标签、哈希和附件为准。

区分已实现、已测试、已发布和许可已确认。测试通过不证明真实账号可用，也不证明第三方授权或完整对应源码已经具备。不要改写旧标签的说明来替代新版本发布。

## 修改后的检查

在仓库根目录执行：

```powershell
node scripts/check-docs.js --all
npm test
git diff --check
```

链接检查覆盖自有文档的普通行内本地链接和标题锚点，不联网验证外链，不解析全部 Markdown 扩展。新增下载地址或外部来源时另行核对目标；不要创建空文件掩盖断链。

新增当前文档应加入[导航](README.md)。命令示例使用仓库相对路径，必要的占位符明确标注；不要将维护者本机产物写成下载地址。
