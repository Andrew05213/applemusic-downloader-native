## 建议测试顺序

1. 启动 `Apple Music Downloader 2.0 Test`。TCG 启动可能等待几十秒，以界面状态为准；无已验证会话时应自动出现一个登录窗口。账号、密码及需要时的验证码都在同一窗口完成，不需要手填 developer token 或 Media-User-Token。
2. 登录后搜索一首账号有权访问的歌曲，先按默认 AAC-LC 下载；检查任务完成回执、实际文件、标签/封面，再试 ALAC 和歌单。默认并行数为 3，可在设置调整。
3. 在目录中点击单个“播放”。完整播放先准备 AAC 文件再播放，不是点击即远端流播；失败且有 preview 时会标为“试听”。请确认实际时长、声音、暂停、定位、切歌和停止，不能只凭按钮状态认定完整播放成功。
4. 正常退出应用，再打开，检查已有会话能否恢复；之后可测试电脑重启。若 Apple 明确要求重新验证，可能仍需验证码，本轮没有承诺永久免验证码。
5. 再测试“我的歌单”、地区、歌词、文件名与失败重试；个人资料库是否可访问取决于实际账号权限，未由空账号 fixture 验证。

登录失败、目录失败、单曲许可失败和文件发布失败是不同问题。请记录失败操作、音质、界面错误码及时间；在“设置与状态”使用“导出诊断”。请勿发送密码、验证码、token 或原始账号镜像。

## 当前测试包：设备验证码登录验收

1. 已有会话先恢复；无已验证会话时使用统一的账号/密码登录窗口，不再有验证方式下拉框、手机号列表或短信发送按钮。
2. Apple 要求验证时，在已登录同一账户的受信任设备上批准本次登录，并填写本次六位验证码；不要使用另一次登录会话的验证码。
3. 只有 Lite 认证和新鲜 Music 会话验证通过才显示成功。之后再测试目录、下载、播放和正常退出后的会话恢复。
4. 旧 `method: sms` 请求和短信路由应被拒绝，不能偷偷切换到密码登录；已验证会话不应因此失效。
5. 失败时导出脱敏诊断。旧短信错误只保留在历史导出中，不应让当前登录界面继续误报短信服务或网络问题。
6. 安装新包后先让已有会话恢复，或点“重新验证会话”。401 会明确显示目录/developer 授权拒绝，不再一律认定账号未登录；403 显示 Music 用户会话拒绝。导出包含 HTTP 状态和已识别的固定 `appleErrorCode`，不会导出错误正文或 token。只有 Apple 明确再次要求验证时才填写本次验证码。
