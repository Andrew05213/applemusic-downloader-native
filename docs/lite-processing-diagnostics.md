# Lite 处理耗时（诊断构建）

在「设置与状态 → 导出诊断」中，`downloadTasks.jobs[].trackTimings` 是客户端曲目统计；`liteProcessing` 是**当前 guest 启动以来**的匿名流汇总（含播放和下载，不含进行中的流）。不会按结束顺序猜测曲目或存储服务原始日志。只保留最近 64 条，`seen` 是收到的有效汇总总数，`omitted` 表示已轮换的条数。重启 guest 会重置；请在测试后、关闭应用前导出。

`available:false` 表示无法取得可靠的快照，不等于零耗时。`available:true,seen:0` 表示当前确实没有已接收的终态汇总。每条记录的 `first`（尝试创建上下文）和 `reuse`（复用上下文）分别汇总；时间单位为纳秒，客户端为毫秒。`held_ns` 包含 `create_ns`、`copy_ns`、`sdk_ns`，不能重复相加。`wait_ns` 只指 Lite 内部的锁；`queueMs` 只指客户端等待。`sdk_ns` 是调用经过的时间，不是纯 CPU 时间。

先确认队列空闲、没有播放，再做单曲；结束后导出，再新建同一任务内三首并发并导出。只在 guest 未重启且期间无其他播放/下载时，用两次快照的新增记录比对；先核对请求数，不匹配时不要归因。并发样本比较合计，不能将匿名流直接对应歌名；累计等待也不能相加当成任务墙钟。
